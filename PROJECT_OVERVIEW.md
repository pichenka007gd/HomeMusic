# HomeMusic: обзор проекта

HomeMusic — музыкальный сервис на собственном сервере: библиотека, плеер,
поиск по внешним площадкам, скачивание и рекомендации по звучанию.
Слушать можно через Android-приложение или браузер.

## Основные возможности

- Музыкальная библиотека с исполнителями, альбомами, обложками и тегами.
- Поиск файлов через YouTube, YouTube Music, SoundCloud и другие подключённые источники.
- Скачивание, проверка аудио, запись метаданных и импорт в библиотеку.
- Импорт коллекций из Яндекс Музыки; обработка ссылок и текстовых списков.
- Личные плейлисты, избранное, очередь и загрузки на телефон в Android.
- «Микс дня», «Моя волна» и рекомендации с учётом истории и доступных аудиовекторов.
- Несколько пользователей, ручное создание аккаунтов и приглашения.
- ИИ-ассистент при отдельно настроенном LLM API.

Каталог Deezer используется для метаданных и коротких превью. Наличие трека
в каталоге не означает, что полная запись доступна для скачивания.
Доступность YouTube и других площадок зависит от сети, cookies и ограничений источника.

## Техническое устройство

```text
Android-приложение / браузер
    ├── Navidrome: аккаунты, библиотека, плейлисты, стриминг
    └── HomeMusic Hub: поиск, импорт, загрузки, рекомендации
            ├── yt-dlp и провайдеры внешних источников
            └── MuQ-MuLan: векторы звучания
```

| Компонент | Назначение и технологии |
| --- | --- |
| Navidrome | Музыкальный каталог и воспроизведение через Subsonic-совместимый API |
| Hub | Python, FastAPI, SQLite и очередь фоновых заданий |
| Веб-интерфейс | React, TypeScript, Vite; установка в качестве PWA при подходящих условиях браузера и HTTPS |
| Android | Форк Tempus: нативный плеер и встроенная веб-вкладка Хаба |
| Embedder | Отдельный Python-сервис с PyTorch и MuQ-MuLan |
| Развёртывание | Docker Compose, постоянные тома и каталоги аудиофайлов |

У Android-плеера и веб-вкладки Хаба отдельные механизмы сессии:
вход в Navidrome должен сопровождаться авторизацией Хаба.
Ошибка встроенной вкладки не обязательно означает неисправность воспроизведения.

## Нейроанализ музыки

MuQ-MuLan строит 512-мерные векторы по фрагментам звучания треков.
В текущей конфигурации анализируется 30-секундный фрагмент из середины записи.
Векторы сохраняются в базе embedder и используются механизмами рекомендаций.
Новые импортированные и связанные с Navidrome треки отправляются на анализ фоновой задачей.

Это не объективная оценка качества музыки. Модель помогает искать похожее звучание,
но не гарантирует точность редких жанровых тегов. Для надёжного определения одинаковых
аудиозаписей нужны отдельные аудиоотпечатки: сравнения названий или embeddings недостаточно.

## Текущая локальная установка

Состояние проверено 12 ноября 2026 года. Детали этого раздела относятся к этой машине,
а не ко всем установкам upstream HomeMusic.

- Запущены Navidrome, Hub, YouTube PO-token provider и embedder.
- Для четырёх контейнеров включён `restart: always`; Docker включён в автозагрузку ОС.
- Используется настоящая модель `OpenMuQ/MuQ-MuLan-large`, не тестовая заглушка.
- Модель работает на CPU: 18 из 28 логических процессоров, лимит памяти 10 ГиБ.
- В проверенной партии обработано 138 треков, ошибок анализа — 0.
- Веса и базы остаются в Docker volumes на SSD.
- Музыка, аудиокеш, корзина, резервные копии и APK перенесены на HDD.
- Cookies YouTube остаются отдельным файлом на SSD и подключены только в Hub.
- Пользовательский таймер `homemusic-youtube-cookies.timer` раз в минуту обновляет
  экспорт только YouTube-cookies из основного профиля Firefox. Файл атомарно заменяется
  только при изменениях; при отсутствии признаков входа предыдущий экспорт сохраняется.
  Таймер работает в пользовательской сессии и не гарантирует принятие cookies YouTube.
- Внешние запросы к выбранным музыкальным источникам проходят через HAPP-прокси.
- HAPP используется без глобального TUN, который мешал входящим подключениям к серверу.

Корень музыкальных данных на HDD:

```text
/run/media/pichenka/1EAE9FF1AE9FC027/HomeMusic
├── library
├── staging
├── .trash
├── .backups
└── .apk
```

HDD — Seagate 500 ГБ, раздел NTFS. Его монтирование уже прописано в `/etc/fstab`.
Для bind mounts отключено автоматическое создание отсутствующих каталогов:
отсутствие HDD должно приводить к ошибке запуска, а не к незаметной записи на системный SSD.
Старые исходные каталоги на SSD пока оставлены как копия для отката.

### Политика хранения

Локальный `config.yaml` содержит:

```yaml
library:
  persistent_audio_cache: true
  min_free_gb: 5
```

- Полные завершённые копии прослушиваемого аудио не удаляются по прежнему трёхчасовому сроку.
- Для новых полных копий сохраняется служебный manifest: кеш доступен после перезапуска
  и истечения кеша метаданных без повторного обращения к исходному сайту.
- Незавершённые файлы без manifest не считаются готовым аудиокешем.
- Старые копии, созданные до включения этой политики, не получают manifest задним числом.
- Облегчённые мобильные версии имеют отдельный вытесняемый кеш до 2500 МиБ.
- Резерв свободного места — 5 ГиБ. Задания скачивания при недостатке места
  откладываются и повторно проверяют диск через пять минут.
- Загрузка файлов с телефона при недостатке места возвращает HTTP 507.
- Ручное удаление и отдельная очистка временных непрослушанных рекомендаций остаются доступны.

Диск не безразмерный: при проверке после переноса на HDD оставалось около 23 ГиБ.
Пространство также могут расходовать другие приложения, поэтому резерв не является дисковой квотой ОС.

### Проверка сервисов

В каталоге проекта выполните:

```bash
docker compose ps
curl -fsS http://127.0.0.1:8080/healthz
docker compose exec -T embedder python -c "import urllib.request; print(urllib.request.urlopen('http://localhost:8090/healthz').read().decode())"
```

Для embedder важны `queue.done`, `queue.error` и `state`, а не один HTTP 200.
После простоя модель может выгружаться из RAM; сохранённые векторы при этом остаются на SSD.
Не запускайте `docker compose down -v`: эта команда удаляет постоянные тома с базами и весами.

## Розовая тема и собственное оформление

Возможно сделать розово-чёрную или пастельную тему, поменять иконки, типографику,
оформление плеера и обложки-заглушки. Редизайн пока не реализован.

| Часть интерфейса | Что потребуется |
| --- | --- |
| Веб-Хаб, включая встроенную вкладку Android | Исходники доступны в `web/`; после изменений нужна пересборка Hub |
| Нативный Android-плеер, навигация и экран входа | Нужны исходники Android-форка, отсутствующие в этом публичном репозитории |

Изменение веб-темы не перекрашивает нативные Android-экраны.
Свой изменённый APK нужно подписать собственным ключом. APK с другой подписью
не установится поверх официальной сборки как обычное обновление.

## Многопользовательский доступ

Для небольшой закрытой компании предусмотрены аккаунты, приглашения, личные
плейлисты и избранное. Аудиофайлы составляют общую серверную библиотеку,
а не полностью изолированные хранилища каждого пользователя.

В текущей установке самостоятельная регистрация по email отключена:
новый аккаунт создаёт администратор в Navidrome либо пользователь по коду приглашения Хаба.

Перед открытием для большого количества пользователей нужны:

1. HTTPS: текущий публичный доступ по HTTP не защищает пароли и сессии TLS.
2. Квоты хранения, загрузок и одновременных запросов.
3. Защита регистрации, мониторинг и проверенные резервные копии.
4. Проверка пропускной способности домашнего интернета и нагрузочные тесты.
5. Проверка прав на музыку: техническая доступность скачивания не разрешает публичную раздачу.

Поддерживаемое количество одновременных пользователей пока не измерялось.
